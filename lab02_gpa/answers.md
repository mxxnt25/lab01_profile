## Q1 · ลำดับเงื่อนไข
ทำไม if ใน `gradeFor()` ต้องเรียงจาก A ลงมา? ถ้าย้าย `if (score >= 50) return 'D';` ขึ้นเป็นบรรทัดแรก `gradeFor(85)` จะได้อะไร? และทำไมคะแนน 101 ต้อง throw แทนการคืน F?

ต้องเรียงจาก A ลงมา เพราะโปรแกรมเจอเงื่อนไขไหนจริงก่อนก็ตอบเลย ไม่ดูต่อ ถ้าเอาบรรทัดของ D ขึ้นไปไว้บนสุด คะแนน 85 ก็จะได้ D เพราะ 85 มากกว่า 50 อยู่แล้ว

ส่วน 101 ไม่ควรได้ F เพราะคะแนนมันเกิน 100 ไม่ได้ แปลว่ากรอกผิด ถ้าให้ F ไปเลยจะไม่มีใครรู้ว่าผิด ตอนลองใส่ 101 แอปขึ้นจอแดงเลย เห็นปัญหาทันที

## Q2 · null safety
ทำไม `nickname` เป็น `String?` แต่ `name` เป็น `String`? `nickname ?? name` ให้ค่าอะไรกับนักศึกษาแต่ละคนในแอปของคุณ?

เพราะทุกคนต้องมีชื่อจริง แต่ไม่ใช่ทุกคนจะมีชื่อเล่น ชื่อเล่นเลยปล่อยว่างได้ ส่วน `nickname ?? name` คือถ้ามีชื่อเล่นก็โชว์ชื่อเล่น ถ้าไม่มีก็โชว์ชื่อจริงแทน

ในแอป Jiratchaya มีชื่อเล่นเลยขึ้นว่า Jirat ส่วน Ploy กับ Kittiphong ไม่มีชื่อเล่น เลยขึ้นชื่อจริง

## Q3 · Layout
ตอนลบ `Expanded` รอบชื่อ คุณเห็นอะไร (คัดลอกข้อความ error) และเพราะอะไร? `LayoutBuilder` ใช้ค่าอะไรเลือก Row หรือ Column และทำไมดีกว่ากำหนดความกว้างตายตัว?

พอลบ Expanded การ์ดของ Kittiphong มีแถบเหลืองดำโผล่ที่ขอบขวา และขึ้น error ว่า
```
A RenderFlex overflowed by 20 pixels on the right.
```
เพราะชื่อยาวเกินการ์ด แล้ว Row ไม่ได้บังคับให้ชื่อขึ้นบรรทัดใหม่ มันเลยล้นออกไป พอใส่ Expanded กลับ ชื่อก็ขึ้นบรรทัดใหม่ได้ปกติ

LayoutBuilder ดูจากความกว้างของจอ (`box.maxWidth`) ถ้ากว้างเกิน 600 ก็เรียงการ์ดเป็นแถวเดียว ถ้าแคบกว่านั้นก็เรียงลงล่าง ดีกว่าตั้งความกว้างไว้ตายตัว เพราะไม่ว่าจะหมุนจอหรือใช้จอขนาดไหน หน้าจอก็ยังจัดได้พอดี ไม่ล้น
